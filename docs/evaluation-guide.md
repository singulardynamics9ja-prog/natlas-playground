# N-ATLAS response review guide

Use this guide when a real model endpoint is available. Demo previews are not model output and must not be included in model-quality ratings.

## Review process

1. Record the test case, selected language, date, and whether the response came from the live endpoint.
2. Ask a fluent speaker to review Yoruba, Hausa, or Igbo output. Record the reviewer's language proficiency (for example, fluent speaker, educator, or translator) without collecting unnecessary personal details.
3. Rate each response independently before comparing it with other responses. Do not treat one translation or wording as the only acceptable answer.
4. Keep the original prompt and response with the rating so reviewers can assess the same evidence.
5. For high-impact claims, verify facts separately. A fluent-language review does not verify factual or professional advice.
6. Note uncertainty and disagreements; seek a second reviewer for disputed translations or consequential issues.

## Rating anchors

- **1 — Unusable:** materially wrong, unsafe, incoherent, or does not address the task.
- **2 — Weak:** substantial errors or omissions; major revision is needed.
- **3 — Mixed:** useful parts, but noticeable errors, awkward language, or incomplete instructions.
- **4 — Good:** accurate and useful with only minor issues.
- **5 — Strong:** accurate, natural, complete, and well matched to the requested audience and task.

Use the three in-app dimensions separately:

- **Helpful:** does the response let the user make progress?
- **Accuracy:** are translations, explanations, and factual statements correct to the reviewer’s knowledge?
- **Relevance:** does it follow the prompt, language, audience, and Nigerian context requested?

For translation cases, check meaning, idiomatic phrasing, spelling/diacritics where relevant, register, and whether the response adds or drops meaning. Record acceptable alternatives and uncertain phrases in reviewer notes; do not grade solely by exact string match.

## Reporting problems

Capture the case, language, exact prompt, response, and concise description of the issue. Remove personal or confidential content before sharing. Flag potential harmful, discriminatory, or high-impact advice for human review rather than treating a single rating as proof of a systematic model defect.

## Privacy and reviewer data

The judge JSON export can contain prompts, responses, timings, and ratings. Review it before sharing and store it only in an approved location. Do not include reviewer names or contact details unless there is a documented need and the reviewer agrees.
